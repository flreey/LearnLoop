# LearnLoop v0.3 — OpenClaw 插件规范对接

## 背景

LearnLoop v0.2 核心功能（afterTask 反思生成）已完成，但插件入口不符合 OpenClaw 插件规范，无法通过 `openclaw plugins install` 加载。本次迭代目标：对接 OpenClaw 插件系统，修复已知 bug，文档对齐。

## 需求清单

### P0 — 集成必须

#### 1. 新建 openclaw.plugin.json

在项目根目录创建 `openclaw.plugin.json`，包含：
- `id`: `"learnloop"`
- `name`: `"LearnLoop"`
- `description`: `"Agent reflection plugin — generates structured reflections after task completion"`
- `configSchema`: JSON Schema，字段包括 `workspaceDir` (string)、`model` (string)，均可选，`additionalProperties: false`

#### 2. 重写插件入口

当前 `src/index.ts` 导出 `createPlugin()` 工厂函数，不符合 OpenClaw 规范。

需要：
- 新建 `src/openclaw-entry.ts`，默认导出 `register(api)` 函数
- 在 `register` 中通过 `api.registerHook()` 注册 `agent:end` 事件
- hook handler 内部调用现有的 `createPlugin().afterTask()` 逻辑
- `package.json` 增加 `openclaw.extensions` 字段指向入口文件
- 保留原有 `src/index.ts` SDK 导出不变（双入口：SDK + OpenClaw 插件）

#### 3. 清理 openclaw-adapter 空目录

删除 `src/openclaw-adapter/` 空目录（如果存在）。

### P1 — Bug 修复

#### 4. 修复 slug 碰撞

当前文件名格式 `YYYY-MM-DD-{slug}.md`，同一天同描述会覆盖。

修复：文件名改为 `YYYY-MM-DD-HHmmss-{slug}.md`，加入时分秒避免碰撞。

#### 5. 同步 I/O 改异步

`src/reflection/index.ts` 中的 `fs.writeFileSync` 和 `fs.mkdirSync` 改为 `fs.promises.writeFile` 和 `fs.promises.mkdir`。函数已经是 async，直接替换即可。

#### 6. Retention 策略

在 `src/reflection/index.ts` 中 `generateAndWriteReflection` 成功写入后，检查 reflections 目录下的文件数量：
- 如果超过可配置的 `maxReflections`（默认 100），删除最旧的文件
- `maxReflections` 加入 `ReflectionConfig` 类型和 `configSchema`

### P2 — 文档对齐

#### 7. 更新 README.md

- 删除 SQLite、BM25、beforeTurn、beforeSpawn、tri-dimensional scoring、memory extraction 等已移除功能的描述
- 对齐 v0.2 实际功能：只有 afterTask hook，文件系统存储反思 markdown
- 更新 Quick Start 中的配置示例
- 更新 Architecture 章节
- 版本号改为 0.3.0

## 约束

- 不改变现有 `createPlugin()` SDK 接口（向后兼容）
- 所有错误静默降级，不向宿主抛异常
- 零新增运行时依赖
