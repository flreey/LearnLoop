# LearnLoop - PRD Discovery Questions (Answered)

## Q1: 记忆提取的 LLM 调用频率与成本控制策略
**Answer**: B — 按 session 粒度，session 结束时（或空闲超过 5 分钟时）提取一次。避免每轮对话都调 LLM。单次对话内的多轮交互，累积后批量提取更高效。另外设置每日调用上限（默认 100 次/天），超限静默跳过。

## Q2: 冲突检测的判断范围与合并策略
**Answer**: C — 保留历史版本链。基于 subject + type 匹配（不做语义匹配，MVP 阶段太复杂），新记忆标记旧记忆为 superseded。confidence 低于旧记忆时仍更新，但保留旧版本。这样既能更新又不丢数据。

## Q3: 记忆注入的 token 预算与优先级淘汰
**Answer**: token 预算 2000 tokens（约占 context window 的 2-3%）。记忆和反思共享预算，按三维分数排序截断，不做 LLM 摘要压缩（增加延迟和成本）。预算可在配置中调整。

## Q4: 成败信号的优先级与冲突解决
**Answer**: A — 按优先级：用户反馈 > review 结果 > re-spawn > 超时。用户反馈是最直接的信号。当用户说"谢谢"但 review FAIL 时，以用户反馈为准（用户可能接受了不完美的结果）。

## Q5: 用户反馈的自然语言分类边界
**Answer**: A — MVP 用关键词规则匹配，无法匹配时标记 neutral，不生成反思。误判的代价确实是污染未来任务，所以宁可漏判（neutral）也不要误判。Phase 2 再考虑 LLM 分类。关键词列表支持中英文，可配置扩展。

## Q6: 反思数据的生命周期与清理策略
**Answer**: MVP 不做自动清理。recency 衰减会自然降低旧记忆的检索优先级，效果等同于软过期。用户可以手动查看和删除（通过 CLI 命令或直接编辑 JSONL 文件）。Phase 2 考虑自动归档（6 个月未访问 → 归档文件）。

## Q7: 多 Agent 场景下的记忆共享边界
**Answer**: B — 反思隔离 + 记忆共享。用户偏好/事实是全局的（"用户喜欢中文"对所有 Agent 都适用），任务反思是 Agent 特定的（韩信的编码经验对墨子没用）。记忆条目不加 agent_id，反思条目保留 agent_id，检索反思时按 agent_id 过滤。

## Q8: Hook 机制的现有能力与异步保证
**Answer**: OpenClaw 的插件 hook 需要先调研确认。MVP 策略：如果 hook 已存在直接使用；如果不存在，通过 cron job + 对话日志分析的方式模拟（每 N 分钟扫描新对话提取记忆）。异步用同进程 Promise（不需要 worker 线程），LLM 调用 2-3 秒不阻塞对话。上一轮记忆没提取完时，下一轮 beforeTurn 使用已有记忆库，不等待。

## Q9: BM25 检索在 MVP 阶段的语言支持
**Answer**: MVP 接受中文检索质量较低。使用简单的字符 n-gram（bigram）分词，不引入 jieba（减少依赖）。中英混合场景存在但不是主要问题——大部分记忆是自然语言描述，不是代码片段。AC-2 性能目标保持不变，n-gram 分词不会显著影响性能。

## Q10: LLM 调用失败的降级策略
**Answer**: B — 静默但记录。失败后重试 1 次（间隔 3 秒），仍失败则跳过并写日志。LLM 持续不可用时（连续 10 次失败），在对话中加一条系统提示通知用户。beforeTurn 检索失败时注入空内容继续对话。
